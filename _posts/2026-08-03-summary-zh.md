## [无状态 MCP 2.0 规范重燃兴趣，催生新工具](https://simonwillison.net/2026/Jul/31/stateless-mcp/#atom-everything) ⭐️ 8.0/10

2026 年 7 月 28 日，Model Context Protocol 发布了 2.0 规范，引入无状态设计，把此前的两次请求握手（初始化加工具调用）合并为一次 HTTP 请求，并使用 MCP-Protocol-Version、Mcp-Method 等新请求头。Simon Willison 称这是 MCP 自发布以来最重大的变化，并在一周内构建了三个实现，包括命令行工具 mcp-explorer 和 datasette-mcp。 去掉服务端的会话状态后，MCP 服务器可以像普通 HTTP 服务一样轻松部署和扩展，开发者不再需要跟踪会话 ID 或把请求路由到同一台后端机器。这降低了构建客户端和服务器的门槛，对所有开发 LLM 智能体框架和工具的人都很重要。 无状态方案通过服务端生成、作为普通工具参数传递的显式句柄来处理跨调用状态（SEP-2567），官方 C# SDK v2.0 已经以无状态优先的方式实现了 2026-07-28 规范，同时保持向后兼容。Willison 指出，相比给智能体一个完整的 shell 环境，MCP 工具更易于审计和控制，而且足够简单，连本地笔记本上运行的小模型也能可靠驱动。

rss · Simon Willison · 7月31日 23:13

**背景**: MCP（Model Context Protocol）是 Anthropic 于 2024 年 11 月推出的标准，用于向基于 LLM 的智能体框架暴露工具，底层基于 HTTP 上的 JSON-RPC 2.0。它在 2025 年掀起巨大关注，但一度被 Anthropic 的 Skills 盖过风头，因为拥有终端访问权限和 curl 的智能体能以更灵活的方式复现 MCP 的大部分功能。此前的有状态设计要求先进行初始化握手以获取 Mcp-Session-Id，然后才能发起任何工具调用。

## [Kakehashi：在 Linux ARM 上运行 macOS 二进制文件的实验性用户空间层](https://github.com/wie-project/kakehashi) ⭐️ 7.0/10

开发者 vlad_kalinkin 发布了 Kakehashi，这是一个实验性的用户空间兼容层，可以在 Linux ARM 机器上原生运行未经修改的 macOS 命令行二进制文件。目前已有 7-Zip、curl（超过 200 条命令和选项通过自动化测试）以及 Xcode Tools Git 的早期可用原型。 如果这个项目成熟起来，Kakehashi 可以让开发者和服务器在更便宜、更普及的 Linux ARM 硬件上无需重新编译就运行 macOS 原生工具，类似于 WINE 和 Proton 让 Windows 软件得以在 Linux 上运行。这填补了一个空白，因为此前没有活跃项目提供在 ARM 上实用的 macOS 到 Linux 二进制兼容方案。 该项目目前仅针对命令行二进制文件，仍处于早期阶段，其中 7-Zip 当前运行速度约比原生 Linux 慢 5.2 倍，不过作者已规划出优化方案。由于 Darwin arm64 和 Linux aarch64 共享相同的指令集，挑战不在于 CPU 模拟，而在于转换可执行文件格式（Mach-O）、系统调用 ABI 以及底层用户空间库。

**背景**: 在 Unix 中，管道或套接字连接着写入端和读取端；当读取端关闭后写入端仍继续写入时，内核会返回 EPIPE 错误并向写入端发送 SIGPIPE 信号。这种情况在把命令输出通过管道传给 head 或 grep 这类读取足够数据后就提前退出的工具时很常见。由于 SIGPIPE 的默认行为是终止进程，开发者通常会显式处理它，而 EPIPE 到底代表成功还是 bug，则取决于程序的具体场景。
